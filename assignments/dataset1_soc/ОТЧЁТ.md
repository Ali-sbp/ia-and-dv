# Датасет 1 — карточки СОК

## Данные и аудитория

Для дежурного аналитика и руководителя СОК: оценить нагрузку, выбрать правила для ревизии и увидеть сегменты, где не хватает вердиктов. Источник — полный учебный экспорт `iavd_incidents_raw_target.parquet` (практика 1.5), **240 295 карточек**, период создания **12.04.2024–03.09.2025 UTC**. Один `EntityId` = одна карточка; в неё может входить несколько алертов. Проверены заполненность ключа, уникальность карточек и читаемость даты. В срезе по умолчанию **164 открытых** карточек (фаза не содержит токена «Закрыт»), **54 870** без указанного вердикта и **150 675** с вердиктом False Positive.

## Что проверили

| Гипотеза | Поля и график | Результат на полной выгрузке |
| --- | --- | --- |
| В будни на календарный день приходится больше карточек, чем в выходные. | `Создан`; два столбца среднего дневного объёма. | Будни: 209 542 / 364 = **575,7**; выходные: 30 753 / 146 = **210,6**. Отношение **2,73×**, гипотеза поддержана. |
| Десять наиболее частых названий правил дают не меньше 30% карточек. | `Наименование`; горизонтальный топ-10 по числу карточек. | **82 222 / 240 295 = 34,2 %**, гипотеза поддержана. Первое правило — `GL_FW_S04_Host_Port_Scan`, 23 998 карточек. |
| У критических карточек доля «Не указан» выше, чем у средней критичности. | `Критичность`, `Вердикт`; 100%-ные составные столбцы. | Критические: **73,1 %** (2 980 из 4 079); средние: **12,6 %** (19 991 из 158 159). Разница **60,4 п.п.**, гипотеза поддержана. |

## Выводы для работы

- Для планирования очереди сравниваем объём в расчёте на календарный день. Праздники отдельно не размечены; первое и последнее число выгрузки покрыты частично. График по месяцам показывает изменения потока, крайние месяцы не сравниваем как полные.
- Топ-10 даёт список кандидатов для ревизии правил. Большой объём сам по себе не означает плохое правило: сначала проверить долю ложных срабатываний, состав трафика и последствия изменения.
- Высокая доля неопределённых вердиктов у критических карточек — повод проверить заполнение и порядок закрытия. Она не говорит, сколько атак пропустила модель. Знаменатель долей — все карточки выбранной группы; на малых срезах учитываем объём.
- Для датасета 1 **False Positive — вердикт аналитика**. Оценка ошибок модели потребует предсказаний и согласованных истинных меток (датасет 2).

Приложение даёт фильтры по датам создания, критичности, источнику и состоянию. Все показатели и графики используют один срез. Составные названия и источники остаются одним значением карточки, поэтому запись не дублируется при подсчёте. Таблица показывает не более 200 самых свежих карточек среза.
